One team, one repository, everybody pushing to it. This is the setup for the
[Semester Project](/teaching/apps-dev/activities/semester-project) — follow it
once at the start and you're done.

::note
Only **one person** creates the repository. The rest of the team joins it as
collaborators. Four repositories is not a team project, it's four solo projects
that happen to have the same name.
::

## Before You Start

Every member of the team needs their **own GitHub account**. No exceptions, no
sharing an account.

Sign up at [github.com](https://github.com) with an email you'll still have
access to at the end of the semester. Write down your **username** — your
teammates need it to add you.

## Create the Repository

::steps{level="3"}

### Click New

From your GitHub dashboard, click the **New** button.

![The GitHub dashboard with the green New repository button highlighted](https://res.cloudinary.com/du6rliaeg/image/upload/v1785597171/click-new_yfuldd.webp)

### Name it and create it

Give it your project name, then click **Create repository**.

Use a name that says what the project is — `cafe-order-system`, not `project`
or `finalproject2`.

![The new repository form with the repository name filled in and the Create repository button below](https://res.cloudinary.com/du6rliaeg/image/upload/v1785597172/name-the-repository_bxbphe.webp)

::

## Push Your Project

::steps{level="3"}

### Open a terminal inside your project folder

Go to your project folder, right-click inside it, and choose **Open in Terminal**
or **Open Git Bash here**.

![Windows right-click context menu inside a project folder showing the Open in Terminal option](https://res.cloudinary.com/du6rliaeg/image/upload/v1785597172/open-terminal-in-project_p103wc.webp)

::warning
Make sure the terminal opens **inside** the project folder, not one level above
it. Push from the wrong folder and you'll upload the wrong files.
::

### Follow the instructions GitHub gives you

Your empty repository page shows the exact commands to run. Use the block
labelled **"…or push an existing repository from the command line"**.

![The GitHub quick setup page showing the command line instructions for pushing an existing repository](https://res.cloudinary.com/du6rliaeg/image/upload/v1785597171/follow-git-instructions_xufgqv.webp)

The commands look like this — copy them from **your** page, since the URL is
different for every repository:

```bash
git init
git add .
git commit -m "first commit"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO-NAME.git
git push -u origin main
```

### Reload the page

Refresh your repository page. Your files should now be listed there.

If the page still shows the setup instructions, the push didn't work — read the
error message in your terminal.

::

## Add Your Teammates

::steps{level="3"}

### Click Settings

Open the **Settings** tab of your repository.

![A GitHub repository page with the Settings tab highlighted](https://res.cloudinary.com/du6rliaeg/image/upload/v1785597172/settings_jq2edj.webp)

### Go to Collaborators, then Add people

In the left sidebar, choose **Collaborators**, then click **Add people**.

![The Collaborators settings page with the Add people button](https://res.cloudinary.com/du6rliaeg/image/upload/v1785597171/collaborators-then-add-peopls_rjjxbp.webp)

### Type their username or email

Enter your teammate's GitHub username or email, then click
**Add to repository**.

Repeat for every teammate.

![The add collaborator dialog with a username typed in and the Add to repository button](https://res.cloudinary.com/du6rliaeg/image/upload/v1785597173/type-username-or-email_aday15.webp)

::warning
Each teammate must **accept the invitation** before they can push. It arrives by
email and also appears in their GitHub notifications.

An unaccepted invitation looks exactly like a working setup right up until the
moment someone tries to push and gets rejected.
::

::

## Your Teammates Join

Once they've accepted, each teammate clones the repository onto their own
machine:

```bash
git clone https://github.com/USERNAME/REPO-NAME.git
```

Use the owner's username in that URL — the repo lives in one place and everyone
clones the same one.

That's it. They can now push to the repository.

## Before Anyone Writes Code

Two things to do once, on every machine.

### Set your Git identity

Use your own name and the email attached to your GitHub account:

```bash
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
```

::note
This is what makes your commits show up as **yours**. Your contribution grade is
read straight off the repository's commit history, so get this right before your
first commit — not after.
::

### Add a .gitignore

Create a file called `.gitignore` in the project root:

```text [.gitignore]
node_modules/
.env
*.log
.DS_Store
```

Never commit `node_modules/`. It's thousands of files your teammates already
have, and it makes the repository unusable.

## The Daily Loop

Every time you sit down to work:

```bash
git pull
```

Work, then:

```bash
git add .
git commit -m "describe what you changed"
git push
```

::tip
`git pull` **before** you start, every single time. Four people editing the same
repository will conflict eventually — pulling first turns "an evening lost to a
merge" into "ten seconds of nothing happening."
::

## When Something Goes Wrong

| Problem                             | What to do                                                               |
| ----------------------------------- | ------------------------------------------------------------------------ |
| `Permission denied` / `403` on push | You weren't added, or you never accepted the invitation                  |
| `rejected — fetch first`            | Someone pushed before you. Run `git pull`, fix any conflicts, push again |
| `not a git repository`              | Your terminal is in the wrong folder                                     |
| Pushed the wrong files              | Add them to `.gitignore`, then `git rm -r --cached <folder>` and commit  |
| I have no idea what I changed       | `git status` and `git diff`                                              |

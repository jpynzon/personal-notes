Every Linux file has an owner, a group, and three permission sets. Once the
`-rwxr-xr--` string clicks, `chmod` stops being guesswork.

## Reading the string

```bash
$ ls -l script.sh
-rwxr-xr-- 1 josh staff 512 Jul 17 10:00 script.sh
```

The first ten characters break down as:

| Chars | Meaning |
| ----- | ------- |
| `-` | Type (`-` file, `d` directory, `l` symlink) |
| `rwx` | **Owner** can read, write, execute |
| `r-x` | **Group** can read, execute |
| `r--` | **Others** can read only |

## Octal notation

Each permission set is a digit: read = 4, write = 2, execute = 1, added together.

| Octal | Permissions | Meaning |
| ----- | ----------- | ------- |
| `755` | `rwxr-xr-x` | Owner full, everyone else read + execute |
| `644` | `rw-r--r--` | Owner read/write, everyone else read |
| `600` | `rw-------` | Owner only — good for secrets |
| `777` | `rwxrwxrwx` | Everyone everything — almost always wrong |

## Changing permissions and ownership

```bash
chmod 755 script.sh          # set with octal
chmod +x script.sh           # add execute for everyone
chmod u+x,go-w script.sh     # symbolic: owner +execute, group/other -write
chown josh:staff file.txt    # change owner and group
chown -R josh ./project      # recurse into a directory
```

::caution
`chmod 777` makes a file world-writable — a common "just make it work" fix that
opens a security hole. Prefer the narrowest permission that works.
::

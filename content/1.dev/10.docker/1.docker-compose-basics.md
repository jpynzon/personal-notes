Compose describes a whole local stack — app, database, cache — in one file, so
`docker compose up` reproduces it anywhere.

## A minimal stack

```yaml [compose.yml]
services:
  app:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://dev:dev@db:5432/app
    depends_on:
      - db

  db:
    image: postgres:16
    environment:
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: dev
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

## Everyday commands

```bash
docker compose up -d        # start in the background
docker compose logs -f app  # follow one service's logs
docker compose exec app sh  # shell into a running container
docker compose down         # stop and remove containers
docker compose down -v      # ...and delete named volumes (wipes the db)
```

::tip
Services reach each other by name over Compose's private network — the app
connects to the database at host `db`, not `localhost`.
::

::caution
`down -v` deletes your volumes and everything in them. Reach for plain `down`
unless you genuinely want a clean database.
::

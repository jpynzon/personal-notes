Nuxt Content v3 rebuilt the query layer on top of SQLite. A few patterns cover
most of what you'll reach for day to day.

## Define collections with a schema

A typed schema turns frontmatter into validated, queryable columns:

```ts [content.config.ts]
import { defineContentConfig, defineCollection, z } from '@nuxt/content'

export default defineContentConfig({
  collections: {
    docs: defineCollection({
      type: 'page',
      source: '**/*.md',
      schema: z.object({
        tags: z.array(z.string()).default([]),
        updatedAt: z.string().optional()
      })
    })
  }
})
```

## Query the collection

::code-group

```ts [List]
const { data } = await useAsyncData('notes', () =>
  queryCollection('docs').order('updatedAt', 'DESC').all()
)
```

```ts [Single page]
const route = useRoute()
const { data } = await useAsyncData(route.path, () =>
  queryCollection('docs').path(route.path).first()
)
```

```ts [Navigation tree]
const { data } = await useAsyncData('nav', () =>
  queryCollectionNavigation('docs')
)
```

::

::warning
Ordering and folder titles come from numeric filename prefixes (`1.intro.md`)
and `.navigation.yml` files — not from frontmatter. Renumbering reorders the
sidebar without changing URLs.
::

## Full-text search

`queryCollectionSearchSections` returns one searchable entry per heading, ready
to feed a client-side fuzzy search:

```ts
const { data: sections } = await useLazyAsyncData(
  'search',
  () => queryCollectionSearchSections('docs'),
  { server: false } // keep the index out of every page payload
)
```

::tip
Loading the search index with `server: false` means it downloads once on the
client instead of being embedded in every prerendered page.
::

Once these become second nature, most loops disappear. Each method answers a
different question about a list.

## The core three

```js
const nums = [1, 2, 3, 4, 5]

nums.map(n => n * 2)          // transform each → [2, 4, 6, 8, 10]
nums.filter(n => n % 2 === 0) // keep some    → [2, 4]
nums.reduce((sum, n) => sum + n, 0) // collapse → 15
```

## Searching and testing

| Method | Question it answers | Returns |
| ------ | ------------------- | ------- |
| `find` | Which item matches? | the item (or `undefined`) |
| `findIndex` | Where is it? | index (or `-1`) |
| `some` | Does any match? | boolean |
| `every` | Do all match? | boolean |
| `includes` | Is this value present? | boolean |

## Choosing the right one

::tip
If you're reaching for `reduce`, first ask whether `map`, `filter`, `find` or
`flatMap` says it more clearly. `reduce` is powerful but easy to make unreadable.
::

```js
// Grouping is a classic reduce
const byType = items.reduce((acc, item) => {
  (acc[item.type] ??= []).push(item)
  return acc
}, {})
```

## Gotchas

::warning
`map`, `filter` and `reduce` return **new** arrays and don't mutate the original.
But `sort` and `reverse` mutate in place — copy first with `[...arr].sort()` if
the original matters.
::

```js
// flatMap = map then flatten one level — great for one-to-many transforms
const tags = posts.flatMap(post => post.tags)
```
